**像连接笔记一样连接标签。**

Tag Ontology 让你可以在侧边栏标签页中为每个标签设置父级、子级和相关标签，无需直接编辑任何文件。随后即可在 Obsidian 原生的**关系图谱**中探索这些结构：按分支折叠与展开、切换至树形布局，并让选中的标签保持聚焦。笔记、笔记间的双链、筛选条件、颜色组与显示设置均保持原有工作方式。

它绝不会修改你的笔记内容。只有当你在侧边栏标签页中添加、编辑或删除标签时，插件才会写入标签字典——这是保管库中的一个纯 JSON 文件。

## 为什么创建 Tag Ontology？

一个概念可以同时连接多个领域。例如，RAG 与 LLM、信息检索和知识图谱都有关联。使用文件夹或嵌套标签整理时，我不得不决定将它放在哪条路径之下，而单一路径很难呈现出它与其他概念的关系。

我希望在保留文档位置与原文的同时，单独管理并探索概念之间的关系。因此，我打造了 Tag Ontology，让标签可以拥有多个父级和相关标签，并能在 Obsidian 的图谱中浏览这些关系。后来我进一步扩展了它，使 CLI 和 TOW 也能复用同一套关系与规则。

> **开始使用：** 标签层级由标签节点构建，因此需要在图谱设置中开启 **筛选 → 标签**。全新安装时会自动为你开启。

## 功能特性

- **在侧边栏中构建层级。** 添加笔记中已使用的标签或新名称，编辑标签的名称、描述、别名、Facet、父级、子级和相关标签，或删除标签。无需编辑文件，且保存时绝不会覆盖来自外部的更改。
- **原生关系图谱的扩展。** 笔记、笔记链接、筛选、颜色组、箭头及其他原生设置照常工作。
- **可折叠的标签层级。** 字典标签初始会折叠至根节点，每篇笔记链接到其最近的可见祖先标签。单击标签可选中，双击可展开一级，此时可以看到笔记移动并连接到更具体的子级标签上。再次双击即可折叠。
- **包含下级的笔记计数。** 对于每个标签，你都可以看到*直接*标记该标签的笔记数，以及包含该标签*或其任意后代标签*的总笔记数。
- **多父级与相关标签。** 实线箭头从父级指向子级，虚线则连接相关标签。
- **四种布局。** 力导向、**思维导图**、垂直树形和水平树形。常规树形布局保留基于当前可见层级的排版方式，并将多个根标签树折行排列。思维导图会从你选择的根标签（第 0 级）开始，并按当前展开的最长父级路径来计算间距。标签着色仍继续采用完整字典的深度。
- **思维导图。** 进入思维导图时，系统会先询问起始位置：搜索层级中的标签，或从推荐的根标签中选择一个，然后仅探索该标签所在的分支。点击底部的**更改起始标签**（主页图标按钮）可返回选择器。切换回其他布局会恢复之前的展开状态；再次进入思维导图时则会重新显示选择器。点击标签文字可在侧边栏查看详情，点击箭头按钮可展开或折叠其子级。拖拽空白背景可平移，滚轮可缩放，点击**适应视图**可使导图完整居中显示。思维导图与原生图谱共享筛选条件与已保存的展开状态。只要仍有另一个已展开的父级连接到共享标签，该共享标签就会保持可见。此布局下会隐藏笔记。
- **3D 视图 (beta)。** 在三维空间中呈现同一套层级：拖拽环绕观察，点击标签即可平滑飞跃至该节点。在图谱工具栏即可切换模式。力导向、思维导图、两种树形布局、3D 与本体浏览器共用同一个标签页；右键点击某个模式按钮可在新标签页中打开，方便对比查看。通过右上角的三段式齿轮设置面板可调整**筛选**（搜索、附件、仅显示已创建的笔记、孤立文件）、**外观**（笔记连线箭头、文本透明度、节点大小、连线粗细、透视缩放标签与标签大小）和**力度**（拖拽张力及各项力度滑块），支持按分组**恢复默认**或面板级**恢复默认设置**。切换至 3D 或本体浏览器时会保留另一侧的画布状态；隐藏时 3D 渲染会暂停，关闭图谱标签页则会释放其资源。
- **本体浏览器 (beta)。** 在空白画布上从一个标签出发，右键即可将它的子级、父级、相关标签和笔记以对象卡片的形式展开，呈现类似 Palantir 本体图谱的交互风格。
- **侧边栏标签页。** 在**文件列表**和**搜索**旁的标签页中按标签名称或别名搜索、查看标签详情，并执行字典检查。在侧边栏中选择标签时，已打开的图谱会自动缩放并居中定位到该标签。
- **字典检查。** 列出保管库中已使用但未收录于字典的标签（附带相似的字典名称）；字典中已定义但尚无笔记使用的标签；将标签写为别名或大小写不同的笔记；以及同时携带上位标签和下位标签的笔记。它仅作报告，绝不会修改任何内容。
- **单一颜色（可选）。** 为图谱和侧边栏中的所有标签统一指定一种颜色，未另行选择时默认跟随主题强调色。
- **按层级深度着色（可选）。** 选择**颜色 → 着色模式 → 按层级深度**，即可根据完整字典中从根标签到当前标签的最长路径为标签着色。筛选与折叠时颜色保持稳定，更深的层级使用调色板的最后一个颜色。**默认**与**柔和粉彩**预设均采用 [Tailwind CSS 3.4 色表](https://v3.tailwindcss.com/docs/customizing-colors)中相同的红→橙→黄→绿→青→蓝→紫→粉顺序，分别对应 500 和 200 色阶。调整层级数时，它们会在整个色域内重新采样；此外还提供**彩虹**、**暖色调**以及单色渐变示例。支持横向编辑带编号的层级颜色并增减层级。图谱左下角的紧凑图例同样支持切换调色板、编辑颜色以及**另存为…**。无论是在图例还是在设置中修改配色，都会保存为共享的**工作副本**，并在重启后自动保留。点击**另存为…**会在**我的调色板**下添加一份独立命名的快照；切换示例或已保存的调色板后，工作副本依然可用。保存的名称必须唯一，绝不会覆盖其他调色板。**我的调色板 → 管理…**会列出已保存的调色板并提供二次确认删除；若删除当前启用的调色板，系统会切回**默认**并保留工作副本。早期自定义调色板会保留为 **My colors**，示例变更时也会保留当前正在使用的配色。色彩设置同步应用于 2D、3D、本体浏览器卡片及侧边栏。灵感源自 [Colored Tags](https://github.com/pfrankov/obsidian-colored-tags)。
- **聚焦（可选）。** 保持选中的标签及其相邻标签（父级、子级和相关标签）高亮，淡化其余节点。还可通过选项一并高亮其所有下级标签和关联笔记。
- **记住视图状态。** 已展开的标签以及**笔记**/**相关标签**开关状态会被自动保存，并在所有图谱标签页间共享。
- **多语言界面（11 种语言）。** 默认自动跟随 Obsidian 语言，也可在**常规 → 语言**中手动切换 English、한국어、日本語、简体中文、繁體中文、Español、Français、Deutsch、Português (Brasil)、Русский 和 Italiano。设置页、侧边栏字典、3D 设置面板、深度图例和图谱视图均会实时更新。

## 工作原理

Tag Ontology 在原生关系图谱内工作。它接收 Obsidian 根据你的筛选条件和颜色组构建好的图谱，折叠字典中的标签，并在标签之间添加层级与相关连线。未收录于字典中的标签仍保持为普通标签节点。局部关系图谱不受影响，禁用本插件后关系图谱即可恢复原样。

3D 视图 (beta) 是一个独立标签页模式。它从保管库中构建同样的笔记和标签，用同一套逻辑叠加字典结构，并通过 three.js 进行绘制。

本体浏览器 (beta) 同样是独立标签页模式。它不会一次性展示整个字典，而是让你逐个将标签放到画布上，并使用 Cytoscape.js 进行绘制。

你在侧边栏标签页中构建的层级保存在字典文件中。如果你想直接阅读或编辑该文件，请参阅[进阶：字典文件](#进阶字典文件)。

标签使用情况来自 Obsidian 的元数据缓存，涵盖每篇 Markdown 笔记的 frontmatter `tags` 与正文中的行内 `#标签`。

## 安装与更新

> 完整步骤、开发版构建及故障排查请参阅[完整安装与更新指南（英文）](../installation.md)。

### 从社区插件市场安装

- **安装**：打开**设置 → 第三方插件 → 浏览**（社区插件市场），搜索 "Tag Ontology"，点击安装并启用。也可以从其[社区插件页面](https://community.obsidian.md/plugins/tag-ontology)安装。
- **更新**：前往**设置 → 第三方插件**，点击**检查更新**，然后点击**全部更新**或 Tag Ontology 旁的**更新**。

### 通过 BRAT（测试版）

- **安装**：
  1. 安装并启用 [BRAT](https://github.com/TfTHacker/obsidian42-brat)。
  2. 选择 **BRAT: Add a beta plugin for testing** 并输入 `NamhyeonKo/obsidian-tag-ontology`。
- **更新**：运行命令 `BRAT: Check for updates to all beta plugins`（或 `BRAT: Check for plugin updates`）。

### 手动安装

- **安装**：
  1. 从[最新发布页面](https://github.com/NamhyeonKo/obsidian-tag-ontology/releases)下载 `main.js`、`manifest.json` 和 `styles.css`。
  2. 将它们复制到保管库内的 `.obsidian/plugins/tag-ontology/` 目录中。
  3. 重新加载 Obsidian，然后在**设置 → 第三方插件**中启用 **Tag Ontology**。
- **更新**：
  1. 下载最新的 `main.js`、`manifest.json` 和 `styles.css`。
  2. 覆盖 `.obsidian/plugins/tag-ontology/` 中的同名文件。
  3. 运行命令 `重新加载 Obsidian（不保存当前编辑内容）`（`Reload app without saving`）或重启 Obsidian。

### 独立 CLI 工具

独立 CLI 已在 npm 上以 [`tag-ontology`](https://www.npmjs.com/package/tag-ontology) 发布：

```sh
# 无需安装，直接运行最新版本：
npx tag-ontology@latest check --root /path/to/vault --json

# 或全局安装 / 更新：
npm install -g tag-ontology@latest
npm update -g tag-ontology
```

> **前提条件**：必须启用核心**关系图谱**插件，并在图谱设置中开启**筛选 → 标签**。

## 使用示例保管库快速开始

仓库的 [`examples/sample-vault`](../../examples/sample-vault) 中内置了一个小型示例保管库：包含 12 个标签的字典和 6 篇笔记。

1. 在 Obsidian 中选择**打开本地仓库**，然后选择 `examples/sample-vault`。
2. 使用上述任一方法在该保管库中安装本插件。
3. 点击左侧功能区的**打开 Tag Ontology** 图标（书本图标），或在命令面板中运行 **Tag Ontology: 打开图谱**。
4. 如果图谱中没有显示标签，请在图谱设置（齿轮图标）中开启**筛选 → 标签**。

你应该会看到两个根标签 `computer-science` 和 `security`，6 篇笔记分别连接在它们上面，此外还有一个未收录于字典的标签 `#to-read`。双击 `computer-science`，再双击 `machine-learning`：`Dropout` 笔记会移动到 `deep-learning` 下。`cryptography` 和 `ai-security` 各有两个父级标签。

接下来可以试试侧边栏标签页：按下 **+** 在 `machine-learning` 下添加一个属于你自己的标签。

## 使用方法

### 侧边栏标签页

点击**打开 Tag Ontology**（书本功能区图标或**打开图谱**命令）会打开关系图谱，并在左侧边栏的**文件列表**和**搜索**旁打开**标签字典**标签页。在图谱中点击标签或点击**字典检查**也会唤醒该标签页。你也可以将该标签页拖拽到右侧边栏。

- **顶部操作栏**：左侧依次为后退、前进和主页（显示根标签与全部标签）；右侧为**新建标签**、**编辑标签**以及用于在图谱中展开或折叠该标签的按钮。若屏幕上还没有打开图谱，点击该按钮会自动打开图谱并定位到该标签；没有子级的标签会显示禁用状态的按钮，提示**无子级标签**。
- **搜索标签或别名**：输入部分标签名称或别名，点击或按回车选择建议项。通过别名匹配时会在标签下方显示对应别名，例如输入 `convolution` 或 `합성곱` 可以找到 `cnn`。图谱会自动展开至所选标签，并将其缩放居中。
- 未选中任何标签时，面板会先列出根标签，然后按首字母顺序依次列出全部标签。滚动列表时，顶部栏与搜索框保持固定。
- 选中标签后，面板会显示其描述、别名、笔记计数（直接计数与含下级计数）、以 `#tag` 链接展示的父级、子级和相关标签，以及关联笔记。点击 `#tag` 即可跳转至对应标签。

### 编辑字典

- **新建标签**（顶部栏的 `+`）：从按使用笔记数排序的列表中选择“笔记已使用但字典缺少的标签”，或者直接输入一个新名称。选择父级可将其置于其他标签之下；不指定父级则会成为根标签。你也可以从字典已有标签中添加子级和相关标签。
- **编辑标签**（铅笔图标）：修改名称、描述、别名、Facet、父级、子级和相关标签。在任一字段的最后一项后点击 **+** 即可新增条目。父级、子级和相关标签必须已存在于字典中，且相关标签会在双向同时保存。重命名标签不会改动使用它的笔记：笔记仍保留原标签，并会在字典中显示为未收录；仅更改大小写（如 `ml` 改为 `ML`）则仍保持关联，因为标签匹配不区分大小写。
- **限制为 kebab-case 标签名**（设置项，默认关闭）：开启后，新建或重命名标签仅允许使用以连字符连接的小写字母与数字（例如 `machine-learning`，即 TOW 所校验的格式）。已有标签名保持不变。
- **删除**（位于编辑表单中）：删除前会弹出确认窗口并列出影响范围——该标签的子级将上移到其父级下（若无父级则成为根标签），它会从各相关标签列表中移除，而笔记仍保留原有标签。
- 所有更改会暂存在表单中直到点击**保存**；若有未保存的更改而离开表单，系统会先弹出提示。如果在你编辑期间，所修改的标签已在外部被改动，保存会中止并提示冲突，你的编辑内容会继续保留在表单中。
- 字典按每个标签一行的格式保存，因此每次保存只会改动相关的行。使用其他排版写入的文件会在首次保存时重新格式化，并保留其原有的换行符格式（LF 或 CRLF）。

### 图谱工具栏

**全部折叠**、**全部展开**与**适应视图**并排位于图谱底部居中位置；其余圆形按钮沿左侧纵向排列，深度图例位于左下角。鼠标悬停在任意按钮上都会显示其名称：

| 按钮 | 功能说明 |
| --- | --- |
| 全部折叠 | 将字典中的所有标签折叠至其根标签 |
| 全部展开 | 展开字典中的所有标签 |
| 适应视图 | 将图谱缩放并居中适应到工具栏、图例和设置按钮未遮挡的视图区域内 |
| 笔记 | 显示或隐藏所有非标签节点（笔记、附件、未解析链接） |
| 相关标签 | 显示或隐藏虚线表示的相关标签连线 |
| 字典检查 | 在侧边栏标签页中列出未收录于字典的标签与未使用的标签 |
| 力导向 / 思维导图 / 垂直树形 / 水平树形 / 3D / 本体浏览器 | 按此顺序在当前标签页中切换模式，当前模式会高亮显示。右键点击任意模式按钮可选择**在新标签页中打开**，以便并排对比两种模式。当对应的**启用**设置关闭时，3D 与本体浏览器按钮会自动隐藏 |

- 在树形布局和思维导图中，每个标签都挂载在其父级下方，并且会隐藏笔记，以保持标签关系清晰可读。
- 在图谱中点击标签会将其居中并在侧边栏标签页中显示详情。双击可展开标签，再次双击可折叠标签，效果与侧边栏顶部按钮一致。其下之前已展开的子标签会在下次展开时保留展开状态。
- 其他操作与原生图谱保持一致：点击笔记可打开该笔记，点击未收录于字典的标签会打开搜索。

### 3D 视图 (beta)

点击图谱工具栏上的 **3D** 模式按钮，或运行**打开 3D 图谱**命令，即可将当前图谱标签页切换至 3D 视图；点击其他模式按钮即可切回。显示其他模式时，3D 渲染会自动暂停。它与 2D 图谱共享已展开的标签、**笔记**与**相关标签**开关、配色、**聚焦**以及侧边栏标签页，因此在一个视图中展开的标签在另一个视图中也会同步展开。

![3D 视图：三维空间中的标签与笔记，图谱后方逐渐淡入背景](../../assets/0.9.0/view-3d.png)

- 拖拽空白区域旋转视角，右键拖拽平移视图，滚动滚轮缩放。
- 拖拽单个节点可将其移开。松手后它会弹回原位，与树形布局类似。布局在打开视图及展开节点后会逐步稳定并保持静止。
- 点击标签可选中并平滑飞跃到该节点，双击可展开或折叠。点击笔记即可打开该笔记。在侧边栏中选择标签同样会飞跃定位过去。在 3D 视图中点击未收录于字典的标签不会触发操作；在 2D 视图中则会打开搜索。
- 工具栏包含**全部折叠**、**全部展开**、**适应视图**、**笔记**、**相关标签**、**字典检查**以及各模式切换按钮。**适应视图**会框选绝大多数可见节点使图谱充满画面；少数距离过远的孤立节点可能会留在视野外。
- 点击右上角的齿轮按钮可打开 3D 设置面板（**筛选**、**外观**、**力度**），结构对应 Obsidian 原生的 2D 图谱面板。面板标题栏提供全局**恢复默认设置**按钮，每个分组内也有各自的**恢复默认**按钮，且所有修改会在全部已打开的 3D 标签页间实时同步。
  - **筛选**：支持 `path:`、`file:`、`tag:`、`-` 否定词及引号短语的搜索输入框；**附件**（默认关闭）；**仅显示已创建的笔记**（默认开启）；以及**孤立文件**（默认开启）。
  - **外观**：笔记连线上的**箭头**（默认关闭；层级连线始终显示箭头）、**文本透明度**、**节点大小**、**连线粗细**、**透视缩放标签**（默认开启）以及**标签大小**（范围 `0.5` 至 `2`，默认 `0.8`）。
  - **力度**：**拖拽张力**（默认开启——拖拽节点时带动相连节点跟随移动；关闭后仅移动拖动的节点）、**图谱向心力**、**节点间的排斥力**、**相连节点间的吸引力**与**连线长度**，各项范围与默认值与 2D 图谱保持一致。拖动任一力度滑块都会重新激活物理模拟。
- 3D 视图直接从保管库构建笔记、标签、附件与未解析链接，并将其齿轮设置与 2D 原生图谱分开保存。
- 如果 3D 视图运行较慢或你不需要使用它，可以在插件设置中关闭**启用 3D 视图 (beta)**。关闭后对应的模式按钮和命令会隐藏，2D 图谱不受影响。

### 本体浏览器 (beta)

点击图谱工具栏上的**本体浏览器**模式按钮，或运行**打开本体浏览器**命令，即可将当前图谱标签页切换至浏览器模式。切换到其他模式时，其画布状态会被保留。它与图谱共用侧边栏标签页，但不共享已展开的标签、**笔记**和**相关标签**开关或**聚焦**状态。

- 面对空白画布时，界面会询问起始方式：搜索标签、选择根标签，或从侧边栏当前选中的标签继续。在侧边栏搜索或点击标签链接也会将其添加到画布中。
- 每个标签都呈现为一张对象卡片，显示其 Facet（未设置时显示为`概念`）、直接关联笔记数、含下级笔记数以及子级数量。不同的 Facet 会拥有各自的配色；未设置 Facet 的标签沿用标签颜色。
- 右键点击标签可使用**展开子级**、**展开父级**、**展开相关**和**显示笔记**，每项都会显示尚未放到画布上的数量。新展开的卡片会整齐排列在两侧列中——子级与笔记位于右侧，父级位于左侧——画布上已有的卡片不会移动。双击标签可直接展开其子级。
- 连线规则与 2D 图谱及字典一致：无论画布上的两个标签是通过哪张卡片引出的，它们之间都会自动连接从父级指向子级的实线箭头以及相关标签间的虚线。
- 关联超过 15 篇笔记的标签会显示为一张分组卡片。点击该分组卡片可在侧边栏标签页中按最新时间优先列出这些笔记，支持筛选并移出勾选的笔记或最近的 10 篇；双击分组卡片会直接移出最近的 10 篇。分组始终包含该标签下尚未以单独卡片形式出现在画布上的所有笔记：之后新标记该标签的笔记会自动加入分组，从画布移除的笔记卡片也会回到分组中。
- 点击卡片可在侧边栏标签页中查看详情；双击笔记卡片可打开对应笔记。你可以将卡片拖拽到画布任意位置并固定在那里。右键点击卡片可将其**从画布移除**；由它展开的其他卡片仍会保留。
- 工具栏提供**适应视图**、**清空画布**以及各模式切换按钮。画布不会持久化保存：关闭标签页后会清空。
- 编辑字典或修改笔记会实时更新画布上的卡片：重命名的标签和笔记会保留在原位，已删除的则会从画布上移除。
- 如果你不需要使用此功能，可以在插件设置中关闭**启用本体浏览器 (beta)**。关闭后其模式按钮和命令会一并隐藏。

## 进阶：字典文件

侧边栏标签页会自动读写此文件，因此你通常无需亲自打开它。它是保管库中的纯 JSON 文件，也可以手动编辑。

字典可以放在保管库内任意以 `.json` 结尾的相对路径下，包括 `tow/` 或 `.tow/` 目录中。当**字典路径**留空时，插件依次查找 `tow/tag-dictionary.json`、`.tow/tag-dictionary.json` 和 `Tag-Dictionary.json`。全新安装会创建 `tow/tag-dictionary.json`；现有的 `Tag-Dictionary.json` 文件继续可用，同时也会继续读取 TOW 0.5.0–0.5.1 的 `.tow/tag-dictionary.json`。如果你手动指定了路径，插件会始终使用该路径。如果字典文件之后缺失，侧边栏标签页会提示创建空白字典。

**Obsidian Sync 不会同步 `.obsidian` 以外以点开头的隐藏文件夹**（参见 [Sync 设置](https://obsidian.md/help/sync/settings)）。如果你使用 Obsidian Sync，请为字典选择一个可见路径。Git 以及按文件同步的工具除非配置忽略，否则都会同步点开头的文件夹。

该文件是一个 JSON 对象。每个键是不带 `#` 的标签名，与原生图谱一样不区分大小写进行匹配（例如 `#ML` 对应键 `ml`）。建议使用全小写键名。像 `#lang/python` 这样的嵌套标签使用键 `lang/python`。

```json
{
  "machine-learning": {
    "aliases": ["ML"],
    "description": "Algorithms that improve at a task by learning from data.",
    "broader": ["computer-science"]
  },
  "dropout": {
    "description": "Randomly disabling units during training to reduce overfitting.",
    "broader": ["deep-learning"],
    "related": ["overfitting"],
    "facet": "technique"
  },
  "computer-science": {
    "description": "The study of computation, information and automation.",
    "broader": []
  }
}
```

| 字段 | 必填 | 类型 | 含义 |
| --- | --- | --- | --- |
| `description` | 是 | string | 显示在侧边栏标签面板中的说明文字。 |
| `aliases` | 否 | string[] | 其他别名。用于搜索匹配，以及在字典检查中为未收录标签推荐相似项。 |
| `broader` | 否 | string[] | 父级标签。**`[]` 表示该标签为根标签。** |
| `related` | 否 | string[] | 非层级关联标签，在图谱中以虚线连接。 |
| `facet` | 否 | string | 自由填写的分类维度，例如 `language`。可在编辑表单或 CLI 变更草稿中设置；当上位标签是标记为 facet 的标签时，与它的下位标签同时出现在笔记中不会被报告为冗余。 |

校验规则：

- **根标签必须显式设置 `"broader": []`。** 完全没有 `broader` 键的标签会被视为尚未归位，不会显示在图谱中。
- `broader` 或 `related` 中引用的每一个标签都必须存在于字典中。
- 标签不能引用自身，且 `broader` 关系不能形成环路。
- 如果字典格式无效，Obsidian 启动或打开视图时会弹出通知提示原因，侧边栏也会持续展示错误信息直到文件修复。在此期间，图谱会沿用上一次成功加载的版本，且**新建标签**和**编辑标签**将暂时禁用。

完整示例请查看 [`examples/sample-vault/tow/tag-dictionary.json`](../../examples/sample-vault/tow/tag-dictionary.json)。

## 隐私与安全

- 无任何网络请求、遥测数据收集或账号体系。
- 仅读取你的笔记元数据与字典文件。
- 插件仅写入自身配置文件（位于配置目录中的 `plugins/tag-ontology/data.json`，通常在 `.obsidian/` 下），以及当你在侧边栏保存更改时写入当前使用的字典文件：你自行选择的路径（包括旧版本中保存的自定义路径），或按自动查找顺序确定的 `tow/tag-dictionary.json`、`.tow/tag-dictionary.json`、`Tag-Dictionary.json`。

## 兼容性与已知限制

- **仅限桌面端。** 已在 Obsidian 1.14.5（macOS）上测试通过。
- 本插件挂载了原生关系图谱的**非公开内部接口**（renderer、PIXI、layout worker）。未来的 Obsidian 更新可能会破坏兼容性。如果检测到内部接口结构陌生，插件会自动脱离挂载并让原生图谱按原本方式运行。
- 在大型保管库中，显示笔记的同时展开全部标签会重绘数千个节点与连线，可能会有短暂卡顿。
- 全部标签展开时标签文字会较为密集，在力导向布局中尤为明显。
- 尚未测试与其他同样修补关系图谱的插件同时使用时的兼容性。
- 3D 视图基于 WebGL 并打包了 three.js，本体浏览器打包了 Cytoscape.js，因此插件包体约为 1.6 MB。不过它们只会在各自标签页打开时才加载。当显示的笔记数量达到数千篇时，3D 视图性能会下降；隐藏笔记可保持流畅。

## 独立库与 CLI

独立的 [`tag-ontology` 软件包](../../packages/tag-ontology/README.md)以 MIT 协议开源了同等规则的 ESM 库与 Node CLI 工具。它可以检查并扫描保管库、统计标签使用情况、展示标签层级，并在执行内容哈希校验的前提下预览或应用字典变更，且无需安装 Obsidian。

该工具已在 npm 上以 [`tag-ontology`](https://www.npmjs.com/package/tag-ontology) 发布：

```sh
npx tag-ontology check --root /path/to/vault --json
```

有关库调用示例请参阅[软件包指南](../../packages/tag-ontology/README.md)，有关子命令、JSON 输出字段、退出码及解析器限制请参阅 [CLI 契约文档](../cli.md)。插件本体与 npm 软件包各自拥有独立的版本号与发布标签。

## 开发

需要 Node.js **22.18 或更高版本**。测试直接利用 Node 内置的 TypeScript 类型剥离能力运行。

```sh
npm ci
npm run lint        # Obsidian 审核规范检查 + 软件包 lint
npm test            # 单元测试，无需准备保管库
npm run build       # 类型检查 + 软件包 dist 构建 + 插件 main.js 构建
npm run check:package  # 检查并试装实际打包的 npm tarball
npm run deploy -- "/path/to/vault"   # 将 main.js、manifest.json、styles.css 复制到保管库
```

`deploy` 命令要求目标保管库中已存在 `.obsidian/` 文件夹，且会保留现有的 `data.json`。部署后请在 Obsidian 中重新加载插件。

`npm run test:vault` 是维护者针对私有保管库（`OBSIDIAN_VAULT_PATH`）运行的集成测试，其他贡献者无需运行。

├── check.ts           # 字典检查中用于归类非规范标签与冗余标签的辅助函数

└── i18n/              # 11 种语言包目录、运行时格式化与实时界面刷新辅助函数
tests/              # node:test 单元测试（tests/integration 仅供维护者使用）
packages/tag-ontology/

├── src/cli/        # 命令行参数解析、JSON 输出结果与退出码
